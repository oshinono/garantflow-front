# Garant Flow — фронтенд

SPA «Учёт заявок на банковские гарантии» на SolidJS + TypeScript. Требования — `tech.md`, эталон UX — `prototype_v10_6.html`.

## Быстрый старт

```bash
corepack enable
yarn install
yarn dev
```

Откроется http://localhost:5173. В dev-режиме по умолчанию включён **мок-бэкенд** (MSW в браузере, `.env.development`), поэтому реальный бэкенд не нужен:

- демо-вход: `demo@garant.local` / `demo12345` (воркспейс с 12 заявками во всех статусах, роль — владелец);
- ещё участники с тем же паролем: `maria@…` (ADMIN), `alexey@…`, `dmitry@…` (MEMBER), домен `garant.local`;
- письма (подтверждение почты, приглашения) не отправляются — ссылка «открыть почтовый ящик» на экране входа;
- «сбросить демо-данные» там же; данные мока и заглушек хранятся в `localStorage` этого браузера.

Работа с настоящим бэкендом: `VITE_API_MOCK=false VITE_PROXY_TARGET=http://localhost:8000 yarn dev` — dev-сервер проксирует `/api` и `/health`.

## Переменные окружения

| Переменная          | По умолчанию            | Назначение                                                                                     |
| ------------------- | ----------------------- | ---------------------------------------------------------------------------------------------- |
| `VITE_API_BASE_URL` | пусто (тот же origin)   | Базовый URL API                                                                                |
| `VITE_PROXY_TARGET` | `http://localhost:8000` | Куда dev-сервер проксирует `/api`                                                              |
| `VITE_USE_STUBS`    | `true`                  | Слой заглушек для функций без API (раздел 8.3 ТЗ). `false` — функции скрыты с пометкой «Скоро» |
| `VITE_API_MOCK`     | `false` (`true` в dev)  | Мок-бэкенд MSW по предварительному контракту                                                   |

## Контракт API и генерация типов

`api.md` и живой `/openapi.json` в репозиторий пока не попали, поэтому контракт восстановлен по ТЗ в `openapi/provisional.yaml` (поля Z-02 расширенного списка заявок там помечены). Типы генерируются из него:

```bash
yarn api:gen
```

Когда бэкенд доступен — генерировать из живой схемы и смотреть, что сломалось в `typecheck`:

```bash
API_SCHEMA_URL=http://localhost:8000/openapi.json yarn api:gen && yarn typecheck
```

Места, где контракт угадан и требует сверки: коды ошибок (`src/api/errors.ts`), матрица прав (`src/domain/permissions.ts`), значения `LawType` (`fz44`, `fz223`, `pp615`, `commercial`), состав `ApplicationSummaryResponse`, пути bank-requests/guarantees, вопросы раздела 8.4 ТЗ.

## Заглушки (раздел 8.3 ТЗ)

Код заглушек — `src/api/stubs/*`, каждая помечена `// STUB Z-xx` и описывает предлагаемый эндпоинт в JSDoc. Данные — в `localStorage` под ключом `stub:<wsId>:<ресурс>`. Хуки над ними (`src/api/queries/stubs.ts` и др.) имеют ту же форму, что будущие реальные: переход на API — замена функции-загрузчика.

| Код                                                                                                                            | Где реализовано                                                          |
| ------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------ |
| Z-01 клиенты                                                                                                                   | `features/application/ClientCombobox.tsx` (собирается из списка заявок)  |
| Z-02 расширенный список                                                                                                        | поля в `ApplicationSummaryResponse` (provisional.yaml), мок их заполняет |
| Z-03 комментарии, Z-09/Z-10 журнал и лента, Z-11 уведомления                                                                   | `api/stubs/collab.ts`                                                    |
| Z-04 предложения, Z-05 лимиты, Z-06 файлы, Z-08 банк заведения, Z-12 воркспейс, Z-13 цвета, Z-14 шаблоны, Z-15 наборы фильтров | `api/stubs/extras.ts`                                                    |
| Z-07 номер заявки                                                                                                              | показываем `number` или хвост UUID; мок нумерует сквозно                 |
| Z-16 отчёты                                                                                                                    | `useIssuedDetails` — детали выданных заявок, ≤ 6 параллельных запросов   |
| Z-17 повторное приглашение                                                                                                     | `useResendInvitation` — отзыв + новое приглашение                        |
| Z-18 массовые операции                                                                                                         | `BoardPage.bulk` — последовательные запросы с итоговым тостом            |

## Структура

```text
openapi/provisional.yaml   предварительный контракт API
src/
  app/        корень, роутер, AuthProvider, WorkspaceProvider, каркас с сайдбаром
  api/        openapi-fetch клиент (токены, single-flight refresh, X-Request-ID), ошибки, хуки TanStack Query, заглушки
  domain/     типы и подписи, ИНН, деньги (big.js), КВ, сроки ОПЗ, фильтры доски, маппинг формы ↔ API, отчёты
  features/   auth, today, board, application (карточка с 5 вкладками), feed, reports, banks, workspaces, notifications, templates
  shared/     UI-кит (Kobalte), хелперы (Excel, хоткеи, localStorage)
  mocks/      мок-бэкенд MSW: одни обработчики для unit, e2e и демо
  styles/     Tailwind v4 + токены прототипа в @theme
e2e/          Playwright
deploy/       пример nginx с SPA-фолбэком и CSP
```

Демо-страница UI-кита — `/dev/ui` (только dev-сборка).

## Что сделано в первой версии и что дальше

Сделано: все экраны из раздела 5 ТЗ на мок-бэкенде; токены в памяти + refresh в `localStorage` с синхронизацией вкладок; доска с поиском, Jira-фильтрами в URL, сортировкой, наборами, DnD и меню «Переместить в…», массовыми действиями и экспортом в Excel; карточка заявки (данные, выдача с КВ в двух режимах, банки с предложениями и комментариями, вложения, история); отчёты и сверка; банки; воркспейсы, участники, приглашения, справочник прав; адаптив до 320 px.

Не сделано / требует внимания:

- сверка с реальным `api.md` и `/openapi.json` (см. выше);
- формы на простых сигналах и valibot, без `@modular-forms/solid`;
- e2e-сценарии покрывают только вход, создание НДС-заявки и архивацию; остальные из 7.4 — следующий этап;
- pre-commit (`lefthook`) настроен в `lefthook.yml`, но репозиторий ещё не инициализирован в git (`git init && yarn lefthook install`);
- Lighthouse и виртуализация колонок > 100 карточек («Показать ещё» есть, виртуализации нет).
